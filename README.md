## 🎯 Цель и философия

**Главная цель:** Написать полноценный 3D RTS движок с гибридной навигацией и тактической глубиной

**Образовательная философия:**
- Понимание КАЖДОГО слоя абстракции
- От простого к сложному через рефакторинг
- Data-oriented design с первого дня
- Сначала геймплей, потом графика

## 🛠️ Технологический стек

### Базовый стек
- **Язык:** C++17 → C++20
- **Сборка:** CMake + vcpkg ✅
- **Тесты:** Catch2 → GoogleTest ✅
- **Профайлинг:** RenderDoc, Nsight, VS Profiler
- **Отладка:** GDB/LLDB, Memory Sanitizers

### Графический стек (эволюционный путь)
1. **Фаза 1:** SDL2 + Примитивы ✅
2. **Фаза 2:** OpenGL 3.3 + Спрайты
3. **Фаза 3:** bgfx (мульти-API)  
4. **Фаза 4:** Vulkan/D3D12 + Продвинутый 3D

### Сетевой стек
- **Transport:** ENet (reliable UDP)
- **Сериализация:** protobuf/flatbuffers
- **Скриптование:** Lua/Sol2 для AI

## 🏗️ Архитектурное видение

### Гибридная 2.75D архитектура
🎮 ГЕЙМПЛЕЙ (ДИСКРЕТНЫЙ) 🎨 ВИЗУАЛ (НЕПРЕРЫВНЫЙ)
↓ ↑
[GameplayNavigation] ←→ [VisualRepresentation]
↓ ↑
[2D+Levels Pathfinding] [3D Render System]

text

### Ключевые архитектурные решения:
1. **Сначала квадратики** → полная игровая логика
2. **Потом спрайты** → базовый визуал  
3. **В конце 3D** → продвинутая графика
4. **Разделение:** геймплейные данные ≠ визуальные
5. **Псевдо-3D:** геймплейный `Vector2` (x, y) + дискретный слой-этаж. Не `Vector3` в симуляции.
   Слои: `Underwater` / `Ground` / `Air`. Высота утёса — свойство тайла, не координата юнита.
   Визуальный z — только в `VisualRepresentation`.

## 🏗️ Фаза 0: Фундамент (2-3 недели) 🔄 В РАБОТЕ

### Математика (`src/math/Vector2.hpp`)
Геймплейная плоскость. Операции:
- `add`, `sub`, `scale`, `length`, `normalize` (ноль → ноль)
- `almostEqual` — сравнение с допуском, не сырой `==` у float
- `distance` — «дошёл до точки», если меньше радиуса прибытия
- Не здесь: `dot` (фаза 3, бой/AI), `Vector3` (не для симуляции)

### Остальное
