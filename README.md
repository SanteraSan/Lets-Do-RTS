## 🎯 Цель и философия

**Главная цель:** Написать полноценный 3D RTS движок с гибридной навигацией и тактической глубиной

**Образовательная философия:**
- Понимание КАЖДОГО слоя абстракции
- От простого к сложному через рефакторинг
- Data-oriented design с первого дня
- Сначала геймплей, потом графика

## 🛠️ Технологический стек

### Базовый стек
- **Язык:** C++17 (C++20 только если без него хуже)
- **Сборка:** CMake + vcpkg
- **Тесты:** Catch2 (не переезжаем на GoogleTest)
- **Профайлинг:** RenderDoc, Nsight
- **Отладка:** GDB, ASan/UBSan на `rts_tests` (не на `rts_game`)

### Графический стек (эволюционный путь)
1. **Фаза 0:** SDL2, окно, примитив юнита = круг + стрелка взгляда (не SVG)
2. **Фаза 2:** OpenGL 3.3 + спрайты
3. Позже по README: bgfx, затем Vulkan. Не подключать заранее

### Сетевой стек
- **Transport:** ENet (reliable UDP)
- **Сериализация:** protobuf **или** flatbuffers — выбрать, когда дойдём до сети, не оба сразу
- **Скриптование:** Lua/Sol2 для AI

## 🏗️ Архитектурное видение

### Гибридная 2.75D архитектура

```
геймплей (дискретный)              визуал (непрерывный)
GameplayNavigation    ←→    VisualRepresentation
2D + слои-этажи                 3D / спрайты (позже)
```

### Ключевые архитектурные решения:
1. **Сначала кружок со стрелкой** → полная игровая логика
2. **Потом спрайты** → базовый визуал  
3. **В конце 3D** → продвинутая графика
4. **Разделение:** геймплейные данные ≠ визуальные
5. **Псевдо-3D:** геймплейный `Vector2` (x, y) + дискретный слой-этаж. Не `Vector3` в симуляции.
   Слои: `Underwater` / `Ground` / `Surface` / `Air`. Одна сетка. Высота утёса — свойство тайла, не координата юнита.
   Визуальный z — только в `VisualRepresentation`.

У полностью закрытого прохода он ждёт секунду, и сдвиг на пиксель это ожидание не сбрасывает. Если проход закрыт стеной, встаёт до нового приказа. Если упёрся в клетку с юнитом, после этой секунды возвращается в центр своей клетки. Лодка и подлодка одну клетку делят
- ✅ Клик по поднятой клетке приказывает именно её, а не землю под ромбом
- ✅ Рампу юнит проходит прямо через центр. Один юнит на прямой клетке подъёма закрывает этот шаг. Обход диагональю в боковой проход — позже
- ✅ Шина событий: подписчик получает опубликованное событие
- ✅ Правый клик публикует приказ, подписчик отправляет выбранного юнита
- ✅ Левый клик публикует выбор, подписчик отмечает юнита
- ✅ Клавиши `1` и `2` публикуют скорость, подписчик ставит её выбранному юниту
- ✅ Сухопутный юнит рисуется спрайтом солдата. Клик по его силуэту выбирает его. Лодка, подлодка и воздух остаются кубами
- ✅ Идущий солдат приподнимается на середине шага и снова встаёт на ноги к следующему. Стоя на месте, он не качается

## ⚙️ Фаза 1: Ядро движка (4-6 недель) 🔄 В РАБОТЕ

### Текущие задачи
Идти по порядку, не пакетом в первый день:

- [x] ECS: `Entity` → `World` → `Transform` (`Vector2` + слой) → одна система движения
- [x] Слои-этажи: `Underwater` / `Ground` / `Surface` / `Air` на одной сетке, не `Vector3` и не отдельная сетка на слой
- [x] Высота препятствия — свойство тайла. Утёс (высота > 0) только для воздуха. Вода (высота < 0) для подводного этажа и воздуха. Земля только на высоте 0. Рампа и площадка пускают наземного
- [x] Сеточная навигация: A* в обход закрытых клеток и юнитов своего слоя. JPS — фаза 3
- [x] Картинка кадра отделена от цикла: `tileAppearance` / `unitColor`, рисование в `drawWorld`. Отдельный компонент на юните — когда внешний вид перестанет совпадать со слоем
- [x] Шина событий: подписчик получает опубликованное событие
- [x] Правый клик публикует приказ, подписчик отправляет выбранного юнита
- [x] Левый клик публикует выбор, подписчик отмечает юнита
- [x] Клавиши `1` и `2` публикуют скорость, подписчик ставит её выбранному юниту
